# Domain docs

## Layout

This repository has one context:

- GLOSSARY.md at the repository root.
- Architecture decisions under docs/adr/.

## Consumer rules

Before exploring, read the root glossary and ADRs relevant to the work.
If GLOSSARY-MAP.md exists, follow it to the relevant glossary instead.

When domain documents are absent, proceed silently. Create them lazily through
domain-modeling when terminology or architectural decisions are resolved.

Use glossary terms in issues, specifications, code, tests, and explanations.
Surface conflicts with an existing ADR explicitly before changing the decision.
